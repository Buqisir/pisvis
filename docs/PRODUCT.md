# 产品方向：自己的物理表达系统，不是每题临时画一张图

更新：2026-09-28（UTC+08）。本文件记录已确认的产品方向和工程决策，不表示这些能力已经实现。
执行入口：[Spec 总纲 #2](https://github.com/Buqisir/pisvis/issues/2)。当前能力以 README 和代码为准。

## 已确认的目标

pisvis 是独立的二维物理教学可视化库：有自己的视觉辨识度；由明确的数学与物理关系驱动；
组件、装置关系和题型模板能够组合、保存、重复使用。老师可以用它表达和探索一道题，
Agent 可以利用已注册能力搭建或修改场景；未来消费方可以是题库、讲题页或其他应用。

“够基础”指核心规则和扩展权掌握在项目中，不指画面简陋，也不指所有通用算法都必须重写。
“现代技术”指采用适合场景、维护状态经过核对、可以验证和替换的技术，不指所有页面必须用最新实验性 GPU API。
“自己的东西”主要在于物理语义、题型、关系约束、教学交互和视觉语言；允许研究和自研基础数学，
但不把通用响应系统、公式排版器或 GPU 渲染器变成产品开工的前置工程。

## 三种复用必须同时进入设计

| 复用层 | 实际复用什么 | 不能冒充复用的做法 |
| --- | --- | --- |
| 部件 | 箭头、坐标轴、物块、标注、样式 token | 每道题复制 SVG 路径再微调 |
| 关系/装置 | 锚点、连接、接触、分量与合量的引用关系 | 只让几条线在视觉上碰到一起 |
| 题型模板 | 适用条件、参数/单位、计算、图形绑定、操作、讲解和测试例 | 一张只能替换文字的截图 |

模板应是可组合的起点，而不是封闭成品。新增关系或模型通过受审查代码和 Spec 扩展，
不要求第一版就能任意混合所有物理模型。复用必须用第二个真实例子证明，不按图元数量计进度。
同模板的实例拥有独立状态；已保存题目引用精确模板版本，升级不能悄悄改题意。

## 核心联系

题目条件与教学目标 → 已知适用条件的模型 → 同一份计算状态 → 情境图 / 公式 / 函数图 / 数值读数。
老师和 Agent 的修改经过同一校验入口；图形不能绕过模型随意改出另一组答案。
布局、视口和主题属于表达方式，不是物理条件。原题模式与探索/变式模式必须明确区分。

把一份数学关系显示成四种视图，与维护四份各自计算的数据，不是同一件事。
详见 [复用与绑定](REUSE_AND_BINDINGS.md)。

## 视觉不是末尾的美化任务

先建立一张维护者认可的可运行样板，再把选择沉淀为 token、图元和状态规范。
候选方向是“轻质感科学插画”与“精密清爽线描”，并非已确认的品牌风格。
颜色、材质、箭头比例、线型、标签和动效应服务教学表达，不能扭曲几何关系或掩盖错误。
视觉是否喜欢由实际样板与维护者反馈判断，不以用了某个库作为美观验收。
详见 [视觉设计](VISUAL_DESIGN.md)。

## 建设顺序

保留 [M1 #1](https://github.com/Buqisir/pisvis/issues/1) 的工程复现与原生拖动任务。
随后 [M2 #3](https://github.com/Buqisir/pisvis/issues/3) 用向量合成/分解验证主题、模板和实例复用；
再由 [M3 #4](https://github.com/Buqisir/pisvis/issues/4) 打通一个水平抛出题型的多视图联系。
原计划中的光滑斜面保留为后续候选；不是要求同时交付两个物理模型。

技术候选全部留档，但只在需要时逐项使用。一个具体问题触发一个隔离实验；
不先做完所有底层工具研究，再开始第一张教学图。

## 这几轮不做

不做完整题库、帐号平台、通用白板、全高中物理求解器、任意公式语言、全套 3D、自动教材抽题或模型 API 服务。
不复制成熟平台的品牌/视觉资产，不把六本教辅上传进公开仓库，不绑定 english-question-bank。
导出/打印有独立边界：可输出简单 SVG 不等于公式、字体、分页和打印已验收。

## 一轮是否成功

维护者能理解它增加了什么、为什么结果可信、哪些条件不能改；换一组题目条件无需重写页面；
同一部件在第二个场景保持外观和行为一致；数值、交互、视觉分别有证据。
未完成的部分显式标注，不把候选依赖、设计草图和 Skill 中的想法写成已存在的 API。
