# 架构起点：小核心，而不是大框架

状态：初始化设计。以下分别说明已落地内容与未来约束，未来目录不是现有 API。

## 1. 为什么从这一层开始

项目的创造空间不只在物理组件：向量、几何、坐标映射、形状生成、场景关系和交互规则都可以自己实现。
浏览器原生 SVG 是显示后端，不替我们决定物理对象。第一版不重写栅格化、字体排版或 GPU 驱动。
“零第三方运行时依赖”是当前核心的选择，不是未来禁止任何合理依赖的教条。

## 2. 现在的真实结构

```text
src/math/vec2.ts       有限数值、向量运算
src/core/viewport.ts   世界与 SVG 逻辑像素坐标互换
src/primitives/arrow.ts 计算箭杆与三角箭头
src/render/svg.ts      纯 SVG 序列化，不访问 DOM
src/index.ts          公共导出
playground/           浏览器专属演示，不进入库构建
skills/               给 Agent 的使用规则，不承担计算
```

依赖方向：`math <- core / primitives <- render <- playground`。
目前没有场景图、约束求解、自动排版、物理模型、仿真时间轴或模型 API 调用。
先保持单包；有第二个真实渲染后端或消费方后，再讨论抽象与拆包。

## 3. 当前必须理解的约定

世界坐标 x 向右、y 向上；内部后续角度统一用弧度，面向老师的角度输入可用度，但必须显式转换。
`Viewport.originPx` 与 `worldToScreen` 的 screen 当前指 **SVG viewBox 内的逻辑像素**，
不是鼠标 `clientX/clientY`，也不是设备物理像素。CSS 响应式缩放是另一个变换。

```text
svgX = originX + worldX * pixelsPerUnit
svgY = originY - worldY * pixelsPerUnit
```

首轮拖动必须先用 SVG 的屏幕变换矩阵求逆，将 client 坐标转为 SVG 用户坐标，再转为世界坐标。
不能简单减页面偏移，也不能忽略 viewBox、滚动、CSS 缩放和留白。
现有正向变换与逆变换都检查统一比例必须为有限正数。

图形坐标没有默认物理单位。以后物理模型内部使用明确单位（例如 SI），显示层用独立比例映射；
不能把显示长度当成力、质量或真实位移。
当前箭头形状函数的输入使用同一坐标系；渲染器先把端点转到 SVG 逻辑像素，再生成箭头，
因此头部不随世界缩放滑块放大，但会随整个 SVG 的 CSS 缩放而变化。不要宣称它始终固定为设备像素。

零向量没有方向：`normalize` 返回 `null`，重合端点输出 `kind: 'zero'` 并显示一个点。
短箭头的头长最多占总长 45%，头宽同比缩小。有限输入若计算溢出，也明确报错。
这些是表示策略，不是物理定律。浮点比较用与量纲、数值尺度相适应的容差，不用一个全局 epsilon 套所有模块。

## 4. 未来增长的方向，不是现在要写的代码

**图形与场景。** 从真实的两个以上图元例子长出轻量场景文档：稳定 ID、明确版本、可序列化纯数据，
以及校验后的修改操作。DOM/SVG 只是场景的投影；不要把 DOM、函数、闭包或可执行表达式存入文档。
将输入校验、解析错误、未知类型、重复 ID、坏引用、对象数/文本长度限制与往返测试一起设计。
在真正需要前不做通用 schema 编译器、自动迁移框架或无限插件协议。

**物理模型。** 图形库负责怎么画，明确的模型负责算什么。两者接口可以共享向量，但不能互相代替。
固定光滑斜面是未来的第一个候选模型，不是任意斜面问题的通解；要交代接触、外力与法向加速度等条件。
分力与合力是表示方式，不能重复算进真实外力；受力图与运动轨迹也要能分别查看。

**时间与数值计算。** 先采用可核对解析结果的小模型。以后再引入数值积分时，要声明步长、误差、停止条件，
并做收敛或守恒量检验。渲染帧率不等于物理步长，暂停/重置/重复播放需要确定性。

**教学表达。** 标签可读、符号一致、黑白也能区分、可逐步显示、支持人工调整。
自动标签避让、复杂公式、打印导出是后续课题，不因为 SVG 可序列化就宣称它们已经完成。

## 5. 安全与可验证性

现有渲染器只有固定标签/属性，数值校验，文字 XML 转义与非法 XML 字符拒绝；不接收任意 SVG 字符串。
初始演示只解析自己的序列化输出，不得把该入口扩成任意 HTML/SVG 上传执行器。
未来 Agent 调用以已注册能力与有限数据为边界，不能把 Skill 当安全沙盒。

正确性分三条验收：数学/几何数值断言；浏览器真实交互；物理假设与结果核对。
单元测试、截图和老师试用相互补充，任何一项都不能代替其他两项。
