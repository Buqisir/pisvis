# 复用、题型与数学绑定契约

状态：设计目标，2026-09-28；以下概念不是现有公共 API。按 M2/M3 实际需要逐步实现，不预建通用框架。

## 1. 拆开五类数据

| 概念 | 职责 | 不应包含 |
| --- | --- | --- |
| 题目实例 | 原始条件、来源定位、教学目标、当前模式 | 为排版编造的物理条件 |
| 模型定义 | 适用假设、输入/单位/范围、纯计算、输出、可核对测试 | DOM、主题或动画缓动 |
| 模板定义 | 选择模型、组合部件/关系、绑定视图、允许命令、讲解步骤 | 某一题共享的可变状态 |
| 实例运行态 | 已验证输入、时间、选择、步骤和派生快照 | 其他实例的状态、可执行用户公式 |
| 表现配置 | 主题、布局、标签偏移、视口和显示比例 | 能反写答案的隐藏数值 |

M2 仅需要数学模板与小实例文档，题目来源/物理模型等字段在 M3 出现时增加。
一个不变的模板可以驱动许多独立实例。两个长得一样的装置不一定适用同一个物理模型。

## 2. 一份有效状态，多种投影

输入/拖动/Agent 命令
→ 解析和结构校验
→ 模板/模型版本与模式权限校验
→ 候选参数的语义校验和完整计算
→ 原子提交有效状态
→ 情境图 / 公式 / 函数图 / 读数。

先完成候选计算再提交。Signals 的 batch 只帮助集中更新，不是数据库事务或失败回滚。
失败要保留最后有效状态，并显示错误；输入框的未完成文字可以独立存在，但不能成为模型的 NaN。
所有视图消费同一快照/版本，不各自重算互相漂移。以后有异步计算时带请求版本，过期结果不能覆盖新状态。

主题/标签/视口只触发表现更新；参数或时间变化才改变对应模型输出。
原题模式锁住已知条件，探索模式保留独立覆盖并标明“已修改条件”，恢复原题不丢原始数据。
这不是考试防作弊或服务端授权系统，本阶段不实现身份权限。

## 3. 约束要可执行，不只写进 Skill

物理约束规定模型何时成立；数学约束规定输入输出关系；表示约束规定图形如何映射量值；
编辑约束规定哪种模式允许改什么。校验和测试执行这些约束，Skill 只指导如何使用。

第一版采用注册到代码的有限模板、明确纯函数和有向依赖；不解释任意公式、不自动解决任意方程组。
Signals 是联动机制，不会推导物理定律或替我们检测所有模型错误。
依赖成环或无法确定更新方向时明确拒绝；以后需要反向拖动求参，须为该操作写可验证的专用逆映射。

布局优化只能移动允许的表现变量，例如标签候选位置；不能为了避让改变长度、质量或速度。
把物理约束作为“允许违反一点的布局损失”不是本项目接受的数学绑定。
KaTeX 的公式文字也不作为计算来源，公式 ID 与模型输出应有显式对应。

## 4. 组件、关系与模板的复用边界

图元提供形状，教学组件增加角色和标注，装置/关系连接锚点，模板组织题型和讲解。
锚点引用对象与局部位置，而不是复制一份以后不会跟随对象变化的屏幕坐标。
连接语义与可视路径独立，图形相交不自动创建连接；分组显示也不自动代表物理刚性约束。

不要为第一根箭头预建所有关系类型。M2 先复用向量合成/分解，M3 将分解组件绑定到速度与不同显示锚点；
有了第二个真实用途再提取共用接口。新增模板优先组合已有组件，而非复制页面。

同模板两实例共享不可变定义，每次构造新的有效状态和资源所有权；深层参数、订阅、宏与随机种子不能无意共享。
销毁接口负责清理监听、effects、动画和后续 GPU 资源；销毁一题不能终止另一题。
多实例的 DOM/SVG ID 使用命名空间，稳定语义 ID 不因重绘改变。

## 5. 存档与版本

**场景文档 v1 已在 arrow@1 落地**（见 Skill references/document.md）：`schemaVersion` /
`instanceId` / `templateId`+`templateVersion` / `unit` / `params` / `presentation`
（theme 精确 id+version、canvas、viewport fit|explicit）。M2/M3 的题型模板必须注册进同一
注册表、复用同一文档基座，不平行造第二种存档格式。

首个文档只保存重建需要的纯数据：schema 版本、实例 ID、精确模板/模型版本、输入条件、单位、
需要持久化的教学状态、主题 ID/版本和有限布局覆盖。物理题可分离原题条件与探索参数。
不序列化 Signal、DOM、GPU 对象、函数、闭包或派生缓存，不从文档下载可执行模板。

schemaVersion 负责文档结构；templateVersion/modelVersion 负责行为；themeVersion 负责外观。
模板注册项指向受审查的代码实现。不能用 latest 解析旧存档；不认识的版本明确报错并保留源文档。
迁移是显式函数并有旧例测试，改变语义的升级需要说明与确认。模板、模型和文档版本不必使用同一计数器。

保存/读取做语义往返测试，不要求属性顺序或生成 SVG 文本完全一样。
同时检查非有限数、未知字段、重复 ID、坏引用和限额（现状：请求 ≤256 KiB、深度 ≤16、
label ≤200、坐标 |v|≤1e6、canvas 64..4096——实现于 src/agent/api.ts）。
不得仅声明 TypeScript 类型后就把不可信 JSON 当合法输入。

## 6. 坐标、单位和时间

保持现有数学世界 x 向右、y 向上；浏览器 client 坐标、SVG 用户坐标、世界坐标和物理 SI 量不能混用。
物理模型指定参考系与原点；教辅使用不同正方向时，来源记录保留原约定，再解释项目转换。
角度内部使用弧度，面向老师可用度并明确转换；无物理单位的数学场景显式标为无量纲。

空间图默认统一缩放；不同物理量有各自显示比例，不能拿像素长度当牛顿或米。
函数图允许轴刻度不同，但标注坐标和单位，不把它当运动情境图。
零向量的方向未定义；溢出/奇点/非法参数不通过随意指定方向或静默夹值来掩盖。

物理时间、播放倍率、帧率和教学步骤分离。解析模型直接以 t 求值；数值仿真未来才引入步长、收敛和误差边界。
重置/暂停/后台恢复有明确规则；在相同 t 与参数下结果可重现。装饰动效不能改变轨迹。

## 7. 对 Agent 的接口方向

创作 API 已在 A1 落地（arrow@1）：`listCapabilities` / `describeCapability` / `createScene` /
`validateScene` / `updateScene`（白名单操作）/ `renderScene`，CLI（`pisvis`）与 MCP
（六个 `pisvis_*` 工具）是同一边界的薄适配。修改操作随能力声明在 describe 的 `operations`
中；M2/M3 新增能力必须复用同一注册表与文档基座，不造平行格式。
先发现真实模板及版本、检查适用条件，再构建实例；未知条件追问或明确标注假设。
Agent 与人工操作走同一命令/校验边界（playground 也是经 API 编辑场景文档），
不能因为是 AI 输出就允许 eval、任意 SVG 或越过原题锁定。

## 8. 必须测试的不变量

同一输入与模型版本产生一致数值；换主题或挪标签不改结果；一题变化不改另一题；
导入失败不部分改写状态；旧版本不被隐式替换；派生箭头和读数在同一时刻；
销毁后不再接收更新；错误/退化场景可解释且仍能恢复操作。

这些是项目自己的设计决策。技术能力来源见 [技术参考](TECH_RADAR.md)，具体物理依据见模型卡和 [教辅地图](CURRICULUM.md)。
