# 有边界的技术实验

状态：候选实验菜单，全部尚未启动。不是要求依次完成的路线图，也不是许可把所有候选包装进主工程。
技术来源与采用级别见 [TECH_RADAR](TECH_RADAR.md)。先完成 M1/M2/M3 主线；
只有一个明确问题出现或维护者明确选择一个研究方向时，才开对应实验 Issue。

## 所有实验的共同约定

一次只回答一个问题。开工前写输入、基线方法、目标设备/浏览器、判断标准和停止条件。
隔离在独立实验目录/分支，依赖和构建不进入默认入口；不提前为未启动实验创建工作区或空包。

必须记录精确版本、来源、许可/资产、可运行命令、输入、实际结果、错误/不支持环境和移除方式。
对比同一数据与任务，不使用不同规模的图来证明某个库更快。结论允许是采用、仅参考或暂不采用。
实验通过也不自动授权更换主状态系统或主渲染器；有收益后通过小 PR 接入并保留回退。

## E1：thi.ng 的一个几何难点

触发：已有明确的曲线采样/求交等需求，自研维护成本开始超过一个小函数。
选一个相关 API，不以重写整个 vec2 为实验目标。

用确定输入比较已有/最小自研与选定函数的数值、退化输入、坐标和可变语义，核对对应正式版本 API。
包括重合、近平行、极小尺度和非法输入中与问题相关的情况。测真实引入函数的产物增量。

采用门槛：复杂度确实减少，边界可解释，pisvis 接口不泄漏上游类型；若收益不明显，保留现有实现并留记录。

## E2：Bloom 的局部标签排布

触发：固定候选锚点加人工微调不能解决反复出现的标签拥挤。
实验只允许移动标签/引线等表现变量；物理对象、几何尺寸、向量和答案都是固定输入。
对比简单候选打分法与 Bloom，不先引入通用物理约束优化。

包括密集长中文、画布太小、不可满足、重复运行和用户固定标签的场景。
记录初始化/更新耗时、稳定性、未满足约束和人工回退。即使优化结束也重新验证硬性边界。

停止条件：依赖代价或不可预测抖动超过收益，或无法避免改变物理条件。此时仅保留架构参考。

## E3：PixiJS 的密集动态 2D

触发：一个有教学目的的密集粒子/场显示，SVG 基线在目标设备实测达不到商定的可用性要求。
小规模静态图不好看不是 GPU 实验的充分理由，先解决视觉设计。

相同模型和输入对比 SVG 与 PixiJS WebGL：首次显示、包体、稳态更新、交互响应、内存、
清晰度与截图差异。记录 CPU/GPU/浏览器、分辨率/DPR、对象数、重复次数；不只报单个平均 FPS。
测容器缩放、无可用 GPU、上下文丢失/恢复、资源销毁及可读的文字/键盘替代路径。
不要假定 PixiJS 自带可用 Canvas 2D fallback，按选定版本核对。

采用门槛：代表场景有可重复收益，能隔离后端与模型，失败不使普通教学图失效。
不在此实验同时启用 TypeGPU，也不承诺完整多后端矢量打印。

## E4：TypeGPU 的二维场实验

触发：维护者选定 GPU 研究方向，或已确认的场计算/表现需求。普通题型先保持可用。
从一个有解析或 CPU 参考的有限网格标量场开始，不一上来写通用流体/电磁求解器。
TypeGPU 与构建插件用匹配版本，不执行网页中的 latest 脚本作为可复现步骤。

CPU 参考与 GPU 输出比较误差，区分数值计算错误和颜色映射错误；记录 f32 等精度选择。
覆盖特性/安全上下文不可用、初始化失败、设备丢失、资源回收和降级。
GPU 不可用时明确提示并给小规模 CPU/静态表达，不能“空白但无错误”。

采用门槛：对该任务确有价值且可复现，不把硬件差异带进题目的数学含义。
实验 Skill 先审查再使用，上游技能不能覆盖仓库安全和交付约束。

## E5：SceneryStack 的教学架构阅读

无需安装就可先回答：怎样组织可观察数据、可访问控件、重置和资源释放？
用一个小参数控件/重置流程整理借鉴点与不采用理由，不照搬整套品牌/仿真页面。
若确实想试一个模块，再量出它的依赖和类型耦合；不可把 Axon 和 Signals 都作为同一状态的权威来源。

阅读笔记可以是成功交付，不必以装包结束。代码与内容/资产许可分别核对，不复制教学素材来省设计工作。

## 结果模板

问题与基线；版本/环境；固定输入和命令；结果表/实际证据；失败与未测项；
模型、视觉和可访问性是否受影响；采用/仅参考/暂缓的理由；下一步最小改动或删除路径。
不以“API 很新”“示例很炫”“仓库很热门”代替项目证据。
