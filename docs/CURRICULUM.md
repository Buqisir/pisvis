## 由题材推导的共用底座（工程判断）

先研究点、线、箭头、圆/弧、折线、文字与分组，再用真实小例子验证坐标轴、角标和锚点关系。
同一个箭头可以表示不同物理量，但图形库不应因为有一个箭头就替用户判定“这是重力”。
曲线图的坐标轴与物理情境图应共享基础几何，不必强行共用同一种物理求解机制。
电路连接关系不等于电路求解；波的空间图不等于某一点的时间图；统计或量子示意不等于真实粒子录像。
这些区别是后续工程审查标准，不是本轮目录阅读推出的具体公式结论。

## 如何把一个条目推进成任务

先选一个非常小的教学场景。针对原文件的具体正文页记录：书名、PDF 页码、印刷页码（能核对时）、
教学目标、假设、参数、图中关系、需要的图元、允许的操作和可验证结果。
明确哪些来自原文，哪些是我们新增的交互设计；无法读到的正文标记待核对，不能用常识冒充阅读结果。
然后在 GitHub Issue 写 Spec，用独立创作的数据与图形做测试。

本轮仅做第一册相关的向量/坐标底座，不顺着这张表同时开工六册。

## 资料处理

PDF 与扫描页留在有权访问的本地资料目录，不进入公开仓库，不把图片转码后隐藏到源码中。
仓库只保留必要的来源定位、抽象需求与独立创作的示例。书名和目录定位不是再分发授权。
后续开发者没有原始文件时，应向维护者索取合法访问来源，而不是自行寻找盗版下载。
